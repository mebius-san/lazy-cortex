# lazycortex-python — minor bump pending publish

**Status**: changed — version `2.1.0` is ahead of the published `2.0.9` at the top of `CHANGELOG.public.md`. Consumers re-run `/lazy-python.install` to pick up the new agent, the review phase, and the expert registration.

## Highlights since 2.0.9

- The check pipeline gained a review phase. `chk review` collects the changed Python files plus every applicable guideline layer and hands them to a new `lazy-python.code-reviewer` agent — covering the rules no AST walk can prove: a purpose comment on every block, logical-block boundaries, naming semantics, and the project's own overlay clauses. It runs as step 7 of `chk all`, reuses its verdict while the scope is unchanged, and never blocks pre-commit or CI on a pending review.
- The guidelines absorbed several rules that used to be project-local: no useless intermediate variables, a purpose comment on every code block, appending to an existing import block instead of opening a new one, the test-edit policy, and a standing prohibition on relaxing a checker at file or directory scope without approval.
- A repo can declare its own runners once — `python.check_cmd` / `python.test_cmd` in `lazy.settings.json` — and every agent and skill invokes those instead of the plugin wrappers.
