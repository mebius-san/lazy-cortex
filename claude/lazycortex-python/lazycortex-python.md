# lazycortex-python — changed since publish

**Status**: changed — version `2.2.0` is ahead of the published `2.1.0`.

## Highlights since 2.1.0

- The review phase now keeps its manifests and findings under `.runtime/lazy-python/review/` instead of `.logs/`. A pending review is unfinished work and a cache keyed by the scope of your diff, not a record of a run that already happened — filing it with the run logs meant it aged out with them and read as history rather than as something still owed. Repos that already have artifacts under the old path can move the directory across; nothing else changes about how the phase is dispatched or rendered.
- A review that has been scoped but never actually read now fails the gate. `chk-py review` exits `2` while a review is pending, so `chk-py all` — and any pre-commit or CI job that runs it — stays red until someone either dispatches the reviewer agent or decides the scope does not need one. Previously the phase printed its manifest and exited `0`, which made passing over it free and invisible: a green gate said nothing about whether the review had happened. Closing it is now a decision someone has to make, and the guidelines say what the two acceptable answers are. `CHK_REVIEW=skip` opts a single run out of the phase for callers that cannot act on it — the shipped docstring and test writers use it, because the session that dispatched them owns the decision, not they. Re-run `/lazy-python.install` to refresh the project's rule mirror.
