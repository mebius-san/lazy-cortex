# lazycortex-python — pending changes

**Status**: changed — `plugin.json` version `4.0.0` has not been published yet (last recorded release: `3.0.0`).

## Highlights since `3.0.0`

- The always-triggered style rule got a size pass: duplicate canon-path pointers and repeated cost justifications are gone, every norm and prohibition intact — about a kilobyte less loaded on each `.py` touch.
- The knowledge-block markers gained their writers: `lazy-python.domain-writer` documents domain mechanics as `Domain(…)` blocks validated against a per-project group dictionary (conventionally `docs/guidelines/domain-groups.md`; when no listed group fits, the block parks under the reserved `unfiled` group and the checker flags it until the operator files it), and `lazy-python.contract-writer` records caller-visible guarantees as `Contract:` blocks and keeps the docstring `Guarantees` section in sync in the same pass. LaTeX is now banned in all code comments, not only in docstrings.
- Knowledge markers are now written by whoever writes the code, not discovered later. Everything the canon said about `Contract:` and `Domain(…)` blocks governed how to *read* a marker somebody had already placed — preserve it, trust it as the source of a `Guarantees` section, never infer more than it states — and nothing said when to place one, so on a codebase where nobody wrote them by hand none ever appeared. The coding canon and the always-loaded style rule now require the marker at writing time: a caller-visible guarantee gets its `Contract:` block with the docstring synced in the same pass, a domain mechanic or formula gets its `Domain(…)` block from the project's dictionary, and the review phase reports the ones that slipped through, since no checker can judge whether a guarantee is present in the code. For code written before this, `/lazy-python.knowledge-sweep` walks the repository with both writers and builds the dictionary with you when the project has none — the dictionary itself is no longer seeded by install, being one project-wide registry shared by every language rather than a Python artifact. The canon also stopped forbidding module docstrings in files that define classes; the prohibition bought nothing and every worker script in the ecosystem contradicted it.
- The parked-knowledge loop now closes instead of dead-ending. A block the writer could not file said "assign a real group" and named no way to do it, so the finding burned on every run with nobody to act on it; the writer itself was forbidden from touching an existing block, so growing the dictionary changed nothing and the same blocks stayed parked. The checker's finding, the style rule, the review checklist, and the style-check pass now all name the sweep as the answer, and the sweep dispatches the writer in a refile mode that re-picks the group for already-parked blocks and rewrites their header line alone, leaving the text underneath byte-identical. A group used in code but absent from the dictionary — a typo, or one somebody invented — is reconciled in the same pass: add it or rename the blocks, the operator's choice. The writer also takes the dictionary path from its dispatch rather than assuming the conventional one, so a project that moved the file no longer has everything parked; and the audit gained a check for the dictionary missing entirely, which nothing on this side could see before, since the checker deliberately never reads it.
- The guideline review left the checker gate and became a phase with a cadence of its own. It used to be the seventh step of `chk-py all`, which meant the inner loop manifested a review scope after every batch of edits and the same file went through a full dispatch as often as it was touched — and each dispatch carries the entire guideline canon, so its cost is fixed per run rather than per reviewed file. Six single-file reviews cost roughly six times one review of the same six files and prove less, since each sees only its own file. `chk-py all` is now six deterministic checks, `chk-py review` stands alone, and the style rule states when to run it: recommended at the end of a logical piece of work and after a subagent cycle that produced substantial Python, mandatory at the end of a full cycle of planned work. Because a unit of work that landed intermediate commits would otherwise get only its tail reviewed, `--base <ref>` scopes the diff to where the work started; an unresolvable ref fails the run rather than reporting an empty scope, which would read exactly like "nothing to review". `CHK_REVIEW=skip` is gone with the problem it solved — it existed so nested writer agents could suppress a phase they had no way to resolve, and they no longer trigger one.
- The source-language norm gained a checker to stand on. Stating it in the canon left it provable only by the review phase, and `ruff`'s homoglyph rule is no substitute — it fires on a Cyrillic word whose first letter looks Latin and says nothing about the rest, so a lowercase Russian sentence in a comment passed every gate. `pcf` now carries `check_language`: `[tool.pcf] allowed_languages` lists the languages a project's comments and docstrings may use (default `["english"]`), admission is by unicode script so one entry covers every language written in it, and an unrecognised name narrows the check rather than widening it. String literals are never scanned — a quoted foreign word is data the code handles — punctuation and separator drawing belong to no script, and one finding per line names the first offending letter with the usual `# waiver:` escape.
- The canon now says out loud that source files are English. It had been assumed everywhere and stated nowhere, so a project whose documents and settings declare another language could reasonably read that as licence to write its comments there — and on a Cyrillic-writing project the result is a file `ruff` rejects outright, since `RUF003` flags every word whose letters have Latin lookalikes. The coding guidelines gained a *Source Language* section putting comments, docstrings, knowledge blocks, log and error strings, and identifiers in English regardless of the project's language, with the translation happening where it belongs: the domain-spec writer renders a group's blocks in the configured language when it generates the document, so the docs speak the project's language and the source stays greppable by a reader of any locale. The style rule carries the one-line prohibition, and both knowledge writers now hold the line even when a dispatch asks them for another language.
- The knowledge sweep stopped sweeping the whole repository, and the dictionary's conventional path moved. `/lazy-python.knowledge-sweep` now takes its scope from `wiki.domains.code` when that section is configured — the same globs the domain-spec generator reads — falling back to every tracked `.py` only when nothing narrower is available; on a repository whose tests outnumber its sources that is the difference between marking the code the generator will read and dispatching two writer agents per test file. The conventional dictionary path is now `docs/guidelines/domain-groups.md` rather than `docs/guidelines/domain_groups.md`: it keeps its place beside the project's other guideline documents and takes the hyphenated name every other registry in the ecosystem carries, and everything that resolves it — the writer agent, the audit's dictionary check, the sweep — follows the settings first and this path second.
