# lazycortex-obsidian — changed since publish

**Status**: changed — version `3.0.0` is ahead of the published `2.2.7`; commits have landed under `claude/lazycortex-obsidian/` since the last release.

## Highlights since 2.2.7

- The tag-page template the vault customises moved to the plugin's own namespace: `.claude/templates/lazy-obsidian.tag-page-template.md`. A vault that already carries the old `obsidian.tag-page-template.md` keeps its customisation — the doctor moves the file to the new name rather than leaving a fresh default beside it, so nothing is orphaned and nothing is overwritten.
- Icon painting moved out of the pre-commit hook and into a routine the daemon runs. The hook wrote `iconize_icon` into the working tree without staging it, which was harmless for a person at a keyboard — the icons rode along in the next commit — and fatal under automation, where the leftover dirt halted the whole runtime after every autonomous commit. A `reconcile-commit` subcommand now reacts to each new commit instead of riding inside one: it repaints whole directories, since a note's colour depends on its neighbours and a matcher callback can key on a file that is not markdown at all — a bumped `plugin.json` repaints its folder note — and it commits notes whose working copy has drifted from the last commit rather than only the ones it rewrote, so an icon the hook left behind in an operator's session is picked up too. All three shipped hooks now check the runtime's hook allow-list and stay silent under the daemon while behaving exactly as before in an operator's own session; `/lazy-obsidian.iconize-install` registers the routine and paints what predates it, and the plugin gained a CLI entrypoint so the daemon can resolve the routine's command at all.
- `/lazy-obsidian.install` splits its two file surfaces apart: rule mirrors are refreshed from the shipped source whenever the bytes differ, while the tag-page template is seeded once and then left to the vault forever — so a customised template survives every plugin update and neither path ever opens a merge prompt.
- Repaint commits now carry their own bot identity (`lazy-obsidian.repaint@bot.invalid`, plus a `Lazy-Bot` trailer), so sibling coordinators — the review and spec loops — no longer mistake an icon repaint for an operator's edit and wake on it. A new `sync-paths` worker op lets those loops repaint the exact notes they are about to commit and fold the paint into the same commit, so most repaints stop producing a separate icons commit at all; `/lazy-obsidian.iconize-install` now also seeds the repaint identity into the consumer's settings so the recognisers know it.
- **Breaking**: the pre-commit shim is gone. `.githooks/pre-commit`, its template, and the `sync-staged` / `install-hooks` subcommands are removed — commit-time repaint belongs entirely to the `lazy-obsidian.repaint` daemon routine, and `check-versions` now reports only the icon-map schema handshake. A vault upgrading from 2.x just re-runs `/lazy-obsidian.iconize-install`: it removes the legacy shim itself (recognised by its `HOOK_VERSION:` marker), unsets `core.hooksPath` when `.githooks/` is left empty, and wires the routine.
- Icons no longer repaint at the end of every assistant turn. The Stop hook the plugin shipped reconciled every directory holding a dirty note, which on a working tree with a few dozen edited files cost tens of seconds per turn — for a cosmetic result the next commit recomputes anyway. Painting still follows each note the assistant writes (the PostToolUse hook) and each staged note (the pre-commit shim); `reconcile-dirty` stays as an operator command for the batches that bypass both, such as a bulk rename or anything written through the shell.
- The plugin now ships a rule of its own, installed into every vault it sets up: the three markdown constructs Obsidian silently reads as structure rather than text. A number, colour, or quoted literal carrying a bare hash becomes an indexed tag; a frontmatter value holding a colon or an opening bracket makes the whole block unparseable, so the note quietly loses its tags and every field a query relies on; a double colon in ordinary prose becomes a dataview field. Each has a one-character escape, and a tag the author actually meant is still written plainly.
