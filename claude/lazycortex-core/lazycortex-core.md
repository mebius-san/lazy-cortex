# lazycortex-core — changed since publish

**Status**: changed — version `5.18.0` is ahead of published `5.17.1`; unpublished commits under `claude/lazycortex-core/` await the next `/pub.publish`.

## Highlights since 5.17.1

- The runtime daemon now picks up its own updates on its own. Previously a plugin update landed in a fresh cache directory while the daemon kept running the version it started on — its restart check compared file contents at paths an update never rewrites, so it never fired in either deployment shape. The daemon now also compares cached version directories, and dev-mode runs the in-repo runner so the loop and its routines share one source tree. Re-run `/lazy-core.install` after updating so the re-rendered supervisor shim reaches the repo.
- Cancelling an expert job now stops its executor instead of deleting evidence: the running process is terminated with a grace window, the bundle stays on disk under a `CANCELLED` marker for post-mortem, the pump and the dead-job doctor leave it alone, and its dedup key is freed so the same work can be dispatched fresh. Cancelled bundles age out with the failed-job cleanup window.
