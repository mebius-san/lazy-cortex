# lazycortex-core — changed since publish

**Status**: changed — version `9.2.0` is ahead of published `9.1.1`; unpublished commits sit under `claude/lazycortex-core/`.

## Highlights since 9.1.1

- The daemon now exports every installed plugin's newest cached version in `LAZYCORTEX_PLUGIN_DIRS` (dev `--plugin-dir` trees first), so routines on a consumer install resolve their sibling plugins without a dev vault; cached versions are compared numerically so `10.0.0` outranks `9.1.1`, and cached roots are never re-passed to `claude -p` as `--plugin-dir`.
- Every `AskUserQuestion` a skill raises now prints a context block first (which skill and step, what was found on disk, why it asks, what each answer does now and later), the question names its target, and options carry descriptions — codified as `lazy-core.skill-writing § 11`, checked by `lazy-core.audit`, and applied to every core skill and command; nine skills that call `AskUserQuestion` without listing it in `allowed-tools` are fixed (`lazy-core.iterate`, `lazy-core.doctor`, `lazy-core.slim-context`, `lazy-guard.allow-mcp`, `lazy-log.clean`, plus four in sibling plugins).
- `default-tiers.json` seeds a `sonnet` tier for the new `lazycortex-specs:lazy-spec.catalog-coordinator` agent, so `/lazy-core.agent-models` pins it without asking.
- A new CLI verb, `routine-ensure-filter`, lets a sibling plugin seed a frontmatter predicate into an existing routine's `filter` block through the boundary-legal contract: only absent keys are planted, an operator's own predicate for the same key is never overwritten, and an unregistered routine is reported rather than created.
