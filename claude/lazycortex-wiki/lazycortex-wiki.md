# lazycortex-wiki — changed since publish

**Status**: changed — version `1.7.1` is ahead of the published `1.7.0`.

## Highlights since 1.7.0

- The core-CLI resolver dropped its second lookup stage, which walked `~/.claude/plugins/cache/` and picked the highest-sorting version directory. That hard-coded a private layout the harness owns and could resolve to a version the user does not have enabled. `$LAZYCORTEX_PLUGIN_DIRS` is now the only channel, and the error raised when it yields nothing names the directories searched and says what to export. A wiki dispatch run from a plain shell, outside the daemon that exports that variable, now fails with that message instead of silently falling back.
- A scope no longer needs an `exclude_paths` entry to keep its own topics index out of the wiki. The resolver recognises the index by the scope's configured `topics_index` path and by the `wiki_role: topics-index` frontmatter marker, and drops it ahead of every other check — so a renamed index, or a neighbouring scope's index caught by the same globs, stays out as well. An operator who forgot the manual entry previously got the index treated as an ordinary document: the curator wrote a summary, tags and a See-also section into it, and the next index rebuild erased all of that without a word.
