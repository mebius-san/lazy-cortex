# lazycortex-wiki — pending changes

**Status**: changed — `plugin.json` version `2.0.0` has not been published yet (last recorded release: `1.8.1`).

## Highlights since `1.8.1`

- **Breaking:** every routine this plugin registers now carries the plugin's own namespace — `lazy-wiki.scan`, `lazy-wiki.relink-weekly`, `lazy-wiki.domain-scan`, and the rest, where they used to be bare `wiki.*`. A repository whose settings still hold the old keys keeps working, but the install skill no longer recognises them: `/lazy-core.doctor` reports the drift and canonicalises it, and nothing rewrites a consumer's settings by force. The skills themselves are also referred to by their real names throughout the documentation now — the short `/wiki.*` form appearing in prose never resolved to anything, since the commands have always been `/lazy-wiki.*`.
- Two knowledge surfaces the rest of the toolchain can query now maintain themselves. A **terms dictionary** — one file per scope, one section per term — keeps a concept from growing a second name: a writing expert asks `/lazy-wiki.terms` for the repository's agreed word before coining one, a curator fills the dictionary from finished documents on a git-watch routine and never edits the documents themselves, and the doctor reports where documents and dictionary have drifted apart, term by term. The **project-structure map** gained the incremental half it was missing: three git-watch routines (changed, deleted, renamed paths) dispatch a curator that keeps `docs/structure.md` matching the tree one change at a time, so the map stops depending on someone remembering to rebuild it. Both are wired per repository through `/lazy-wiki.configure terms` and `/lazy-wiki.configure structure`, and both stay silent until you configure them.
- Mirror scopes now ride the core CLI's `remote-mirror` transport for the clone-and-update step instead of carrying their own git plumbing, and a transport failure of any kind — unreachable remote, unresolvable core CLI, malformed primitive output — comes back as a plain error string rather than a traceback; the merge that preserves the consumer's curation layer stays wholly in the wiki.
- The terms-dictionary wizard's source-exclusion seeds caught up with the specs plugin's tool model: the build-journal exclusions now name all four tool reports (`code-report`, `data-report`, `docs-report`, `test-report`) plus any operator-declared tool's own report document, and the plan-document question asks about `code-plan` under its current name.
- The wiki's query surface now serves one-shot workers, not just the main session. `/lazy-wiki.query` gained an agentless mode: an expert job or subagent that cannot spawn its own subagents reads the scope's topic index itself and walks the glossed links, while a session that carries the Agent tool keeps the fan-out path and its context protection. A new `/lazy-wiki.domains` research skill answers group and term questions with a bounded slice of the domain tree — one document's section or matching excerpts, never the whole tree — and the domain documents themselves gained a Contracts section: `Contract:` blocks are attributed to the nearest `Domain(…)` group in the same file and rendered with the guarantee text and a `path:symbol` anchor, so a writer can read a module's caller-visible guarantees without opening its source. The structure and domains query skills both carry the `research: true` marker that research-gathering agents discover them by.
- **Breaking:** links between wiki nodes are now local paths only. The `@<repo-key>/…` form and the `repos`-registry lookup behind it are gone: a link that reached into another checkout on the same machine resolved differently on every machine and could not be curated at all, since the wiki never writes into a foreign repo. External material a scope needs is brought in instead — a scope may declare a `mirror` block naming a source repository, the markdown globs to take from it, and the vault directory to keep the copy in; a scheduled sync clones the source, mirrors the matching documents, and the ordinary scan curates them like any other node. The sync replaces each document's body from the source but keeps everything the consumer owns on it — the summary, the wiki tag subset, the operator's pins, and the protected See-also block — so curation survives every refresh and a document whose body actually changed goes back through the curator on its own. **Every existing `@<repo-key>/…` link must be rewritten or removed before updating**; the doctor reports the leftovers, and it gained checks for a mirror directory the scope's own globs do not cover, a clone that stopped being fetched, and a mirrored body edited by hand.
- Domain knowledge recorded in code as `Domain(…)` marker blocks now materialises as a documentation tree the rest of the world can read. A new settings section names the code to scan, the project's domain-groups dictionary, the output directory, and the language to write in; a git-watch routine notices when a group's blocks actually changed — the content hash lives in the generated document itself, so the detection works on any checkout — and a writer agent rewrites that group's document whole, with fixed Terms / Principles / Mechanics sections, formulas checked against the code and written as LaTeX, and no links back into sources a foreign repository could not open. An index of the groups sits at the root of the tree; `/lazy-wiki.domain-sync` runs the whole pass by hand where no daemon does it, and the doctor reports a missing dictionary, a group the dictionary does not list, and a document whose hash no longer matches the code.

- The vault gained a project-structure service: one repository-wide map at the fixed conventional path `docs/structure.md` (no scopes, no configurable location — like a README), a `structure` settings section holding depth profiles and excludes, and a new `/lazy-wiki.structure` pull-skill with two modes — rebuild the map from the tree, or answer a query with just the matching subtree instead of the whole file. The spec system's architect reads the map through it before designing anything; curation routines are a later stage, until then the map is maintained by hand or by code-sync passes.
- Two resolution bugs the knowledge-marker pass exposed are fixed. A See-also target was resolved against the node's own directory before anything checked where that landed, so a target spelled with enough `../` segments resolved to a file outside the repository and was returned as a neighbour — only the widening stage was ever bounded. And a curation job's deduplication key took an absolute node path verbatim while resolving the relative one, so the same node reached through a symlinked prefix produced a second key and a second queued job. Both now resolve the path first and bound it to the repository.
- The domain-spec writer's language instruction stopped hedging. It used to say the blocks in code are "typically" English and to translate when the target language differs, which left the writer guessing on a project whose documents are written in another language; now the contract is explicit — source is English, this document is where the project's language first appears, and translating faithfully is the writer's job, with a term the project already agreed on winning over a literal rendering and identifiers, paths, and code fragments staying verbatim.
- The domain-groups dictionary's conventional filename changed: a project that does not configure `wiki.domains.dictionary` now gets `docs/guidelines/domain-groups.md`, where `docs/guidelines/domain_groups.md` used to be assumed. The dictionary stays in the guidelines directory and takes the hyphenated name the rest of the ecosystem's registries carry; a project that already carries one at the old name keeps working by naming it in the settings, and the configure wizard offers the new default when creating one.

- `/lazy-wiki.install` syncs the navigation rule with the deterministic file-sync primitive instead of reading the two copies and judging, which used to report a lagging rule as an unresolvable conflict. The rule's `## Coverage` section is rebuilt from the configured scopes after the refresh, so the scope list is derived rather than preserved.
- The curator is now told how the vault writes markdown. `/lazy-wiki.install` attaches the shared style conventions to the routines whose jobs touch note content — the git-watch scan and the weekly full pass — so a summary, a tag value, or a See-also gloss is written the same way the rest of the vault is, instead of however the model felt like phrasing it that run. Re-run `/lazy-wiki.install` to pick it up; the deletion-pruning routine gets nothing, since it rewrites links by itself and dispatches no expert.
- A domain document whose group left the dictionary is now removed rather than left behind forever. Renaming a group used to strand its document in the tree — the group still had blocks in the code, so nothing counted it as orphaned, and the doctor could only keep reporting it — and the stale copy travelled onward to every consumer mirroring the tree. Such documents now ride the same removal path as those whose blocks disappeared, counted separately in the plan and named individually in the sync report and the commit subject, so a deletion is never silent. The doctor also learned three checks it was missing: a group the dictionary lists without a gloss, a generated tree a wiki scope's own globs have started claiming (two writers on one file, previously caught only by the wizard at configuration time), and it now routes a missing dictionary or an unknown group to the sweep that actually builds a populated one.
- The doctor's deterministic repairs now run themselves: a new daily `lazy-wiki.doctor-apply` routine sweeps every scope with `doctor --apply --commit`, applying only the fixable finding set (index desync, orphan topics, broken or stale See-also lines) and committing the repairs under its own bot identity — mirror findings and anything content-shaped stay reports. The `--commit` flag is new on the CLI too; a hand-run `doctor --apply` without it still leaves the repairs uncommitted for inspection. Re-run `/lazy-wiki.install` to register the routine.
- The classification vocabulary and the exclusion list both moved up to the vault. `wiki.tag_axes` now declares the closed axis set once for the whole repository, a scope's own list only narrows it, and `ensure-axes` writes that vocabulary with no per-scope targeting; `wiki.exclude` applies to every scope on top of its own `exclude_paths`, and the generated domain-spec tree is excluded from every scope structurally — derived from `wiki.domains.output`, so no configuration can hand a generated document to the curator. A new `ensure-scope-config` CLI verb lets a neighbouring plugin seed a scope's filter predicates and exclude globs idempotently, never overwriting an operator's own predicate for the same key; the settings ladder carries a `wiki` v1 → v2 migration that hoists existing per-scope axes into the union and moves the structure-map exclusion to the section.
