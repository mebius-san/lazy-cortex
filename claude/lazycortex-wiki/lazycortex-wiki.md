# lazycortex-wiki — pending changes

**Status**: changed — version `2.2.0` is ahead of the published `2.1.0` in `CHANGELOG.public.md`.

## Highlights since 2.1.0

- A tag canon now exists: the new `wiki.tag-curator` expert consolidates each surface's axis values on a schedule, generated domain docs join the tag surfaces it can normalise, the doctor flags an unknown axis, and the tag dictionary lives at `docs/tags.md` by default.
- The terms curator now reads the changed document straight from the working tree, so terms-scan routines work again — they previously failed on every run waiting for a document copy the runtime never delivers.
- The structure map's scan routine now watches new files only: a content edit never changes the tree shape the map describes, so it no longer costs one curator job per modified file (deletes and renames keep their own routines, and drift in a per-file description stays `report`'s finding and `rebuild`'s repair). `/lazy-wiki.configure structure` also builds the initial map itself when `docs/structure.md` is missing, instead of leaving it to a printed pointer, and the doctor flags a wrong `watch` or routines registered with no map on disk.
