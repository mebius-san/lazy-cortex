# lazycortex-specs — changed since publish

**Status**: changed — version `7.4.0` is ahead of published `7.3.1`; unpublished commits sit under `claude/lazycortex-specs/`.

## Highlights since 7.3.1

- The two tech templates now carry verbatim canon with attribution in every section comment (arc42 §2, §3, §4, §7, §9 and §10, IEEE Std 1016-2009 §5.2.1, ISO/IEC 25010:2023), in place of the home-grown descriptions they shipped with.
- Sibling-CLI resolution (`lazycortex-core`, `lazycortex-review`, `lazycortex-obsidian`) falls back to the plugin cache the plugin itself runs from, so gate dispatch, upstream ticks, request routing, and inline icon repaint work on a consumer install with no daemon export; the drive and install skills pick cached versions numerically.
- Every question `lazy-spec.*` skills raise now prints a context block first (which skill and step, what was found, why it asks, what each answer does now and later) and names its target, so the operator can answer without reading the SKILL.md.
- `/lazy-spec.install` seeds the request inbox (`<vault_root>/requests/**`) into the spec catalog's wiki scope alongside the plan and report working papers, so no wiki wizard has to ask for it.
- A second coordinator, `spec.catalog-coordinator`, now owns the system-level documents of the catalog root and of every product root through their level notes (`spec_role: catalog` / `product`, four derived gates, launch rows for design / ui-design / tech): review approvals promote `spec_stage`, a released asset can raise `Revise design`, a re-approved vision or design drops change-request candidates into the inbox instead of waking assets, and the request router gains `spawn-product` and `attach` on a level document. `tech.md` is narrowed to stack, platforms, constraints, infrastructure decisions and boundaries with no code sync; `spec_source_docs` no longer links upstream level docs; new verbs `catalog-note backfill`, `request-draft`, `seed-doc --root`.
- Level gates for design, ui-design and tech count an absent document as done (only vision needs an approved file); level notes are never recoloured by gates; `spawn-product` needs no precondition; `lazy-spec.sync-with-code` no longer rewrites `tech.md`; a readiness crossing flipped by a bot commit still wakes dependents; and every stage, state and upstream matcher in the spec icon registry keeps the note's type icon and changes only its colour.
- A sixth stage, `deferred`, parks a document the operator may still edit: a change to it wakes the owning coordinator so the folder note gets its gates and brief, but the document itself is never edited, promoted or replaced, closes no gate, and gets a `Review <doc>` launch row whose tick moves it to `draft` and opens its review, so a backlog is worked from Obsidian alone. Documents `lazy-spec.sync-with-code` creates are born deferred, and the install seeds a `spec_stage` predicate into the wiki routines so parked documents dispatch no curator.
- Every callout that carries a checkbox — a launch row, a coordinator `[!question]` — keeps its hint or attribution behind a blank quoted line, never glued to the checkbox item: Obsidian's task renderer shows an item's first line only, so a glued hint was invisible in reading view. The shape is fixed in the layout protocol and both coordinator playbooks.
- `lazy-spec.flip-gate` no longer appends a `[!gate] <gate> — flipped …` record to `# Gates` on every flip: a gate's state is its frontmatter boolean and its transition the `# History` line, so the callout only duplicated both and accumulated forever. The flip's reason (with its `auto:` mark) lives in the run log; `# Gates` now holds launch checkboxes alone.
