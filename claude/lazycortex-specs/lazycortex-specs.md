# lazycortex-specs — changed since publish

**Status**: changed — version `6.1.0` is ahead of the published `6.0.1`; the pending cycle below ships with the next publish.

## Highlights since 6.0.1

- Every spec writer is now obliged to resolve the document's effective language via the `resolve-language` primitive before writing (expert-signals protocol v4) — reports no longer fall back to the templates' English when the vault is configured for another language.
- Spec routines (`lazy-spec.gate-tick`, `lazy-spec.coordinator-watch`, `lazy-spec.request-open`, `lazy-spec.request-apply`) are registered unconditionally — the install skill no longer reads `daemon.enabled`, so a hand-ticked repo gets the whole set.
- Spec skills state their execution order through a written-out step ledger instead of the Task checklist tool, including the runtime-computed diagram seam list in `/lazy-spec.sync-with-code` and the mode-specific step lists `/lazy-spec.create-from-code` picks after mode detection.
- The coordinator picks its review verb by criterion — `submit` when content is already written, `start` when a writer round is needed — so accepted decision-candidates now legalize into an already-finalized living doc: the coordinator carries the accepted blocks in and re-opens the review at the writer round instead of dispatching a bare job that strands its edit in `result/`.
- Two new opt-in document types — use-cases and UI design — join the definition chain, each with its own template, review class, and a step in the feature and change playbooks that waits on them before architecture is written.
