# lazycortex-specs — changed since publish

**Status**: changed — version `7.0.0` is ahead of published `6.3.0`; unpublished work has landed under `claude/lazycortex-specs/`.

## Highlights since 6.3.0

- Design documents now carry a declared abstraction height: a new doc-height protocol tells the writer and validators of the `design` and `system-design` review classes what level their document speaks at and to delegate lower-level mechanics downward instead of elaborating them in place. The install seed attaches it to both classes.
- Breaking renames: `lazy-spec.finalize-branch` is now `lazy-spec.rebase-pins` and `lazy-spec.decide` is now `lazy-spec.record-decision` — the old skill names are gone with no aliases. The plugin's self-audit skill (`lazy-spec.audit`) is removed from the public surface; its checks live in the maintainer's own tooling.
- A new `vision` document kind opens the reading chain vision → use-cases → design → tech: goals and value live only in a vision, the content-root vault spec becomes `vision.md` (seeded by install, gated by product registration, with pre-vision vaults accepted), products get a vision seeded at creation, and features get one seeded by the coordinator before their design. Two review classes (`vision`, `system-vision`) ship in the install seed and reach existing vaults through the v10 → v11 review settings migration, which also lets the `use-cases` class cover a content-root `use-cases.md`.
- The decisions registry gains a third, project-wide level: `specs/decisions.md` at the content-root, lazily created by the `decide` primitive like its product- and asset-level siblings.
- Document templates explain their sections with HTML comments instead of italic placeholder text, so an untouched template honestly reads as empty; design templates drop their Goals section in favour of the sibling vision and gain a worked-`Risks` section.

- Project-level source pins no longer carry a product axis, and the create-from-code and create-asset flows author the vision document, offer the opt-in documents, and mark decision forks.
- The promote primitive replaces a `[!decision]` block with a self-describing line — the record link followed by the thesis — instead of a bare wikilink, so an unwoven replacement still reads on its own.
- The coordinator-dispatch worker derives the commit sha and author for a path-only wake item, so a manual (no-daemon) wake no longer re-fires forever on operator commits it has already handled.
