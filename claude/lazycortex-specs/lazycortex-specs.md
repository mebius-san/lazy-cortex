# lazycortex-specs — pending changes

**Status**: changed — `plugin.json` version `6.0.0` has not been published yet (last recorded release: `3.6.3`).

## Highlights since `3.6.3`

- The plugin now declares the review plugin it has always needed: `lazycortex-review` joins the manifest's dependencies, so a fresh install pulls it in instead of letting the request pipeline die on an unresolved CLI at the first `open_request` / `apply_request` / `flip_gate` call.
- Opening a request stopped hand-writing the review plugin's half of the opt-in shape and asks the review CLI for it instead, so the two copies can no longer drift apart and leave the coordinator repairing every incoming request. Resolving a sibling plugin's CLI is one shared helper now rather than a walk repeated per module, and it is bounded by a timeout that actually fits inside the routine's own budget.
- Renaming a document type now carries everything that answers to the old name: per-category template copies in both the plugin tree and a consumer's own `.claude/templates/` overrides move with the type (their frontmatter keys rewritten), documents' `spec_role` values follow when they match, whitespace-padded frontmatter lines are recognized, and a file already sitting under the new name is never overwritten — the report gained `copies` and `roles` counters for the new ground it covers.
- Shipped sources no longer point at dev-vault-only artifacts: skill and reference prose, comments, and docstrings that named internal rules a consumer never receives now state the contract in their own words.
- The coordinator's common playbook shrank by a third for the frequent wakes: six mode-specific chapters (request routing, multi-step commands, asset creation, upstream cross-asset scenarios, decision sources, spec-only mode) moved into their own references that the coordinator reads only when the wake or the asset's facts call for them, each leaving behind a summary stating its load condition.
- Narrative `# History` lines the bin primitives write on notes (scaffold record, halt, job done/cancelled/died, review opened, coordinator wake, processed request) and the halt's persistent `[!failure]` Gates callout now render in the vault's authoring language through one shared template table, with English as the floor; the dedup and idempotence checks recognize an event recorded under any language, so switching a vault's language never makes old records invisible.
- The retired `dev-plan` / `dev-report` names are gone from every shipped surface: the hand-renamed `code-plan` / `code-report` templates no longer seed documents carrying the old type in their own frontmatter and headings, and the install skill's seeded review classes, help chapters, references, and skill prose all speak the current names.
- Group folders stopped being pre-created: product registration no longer plants empty `features/` / `changes/` / `bugs/` directories, and the first asset landing in any group folder — shipped or operator-declared — creates it and seeds its operator-zone folder-note, painted with the icon of the type whose `default_path` names that folder (an ad-hoc folder gets a plain note). The scaffold reports the seeded note as a new `group_note` result key so callers commit it alongside the asset.
- The code-sync checkpoint follows the vault's tracked-state convention: it lives at `.state/lazy-spec.sync-<product>.json` now, and a repo still carrying the older `spec-sync-<product>.json` name has it renamed automatically on the next sync run.
- The catalog's directory structure is the operator's alone now: a product registers with a free-form key and an arbitrary `spec_path`, the subsystem/namespace concepts and the compound-key derivation formula are gone, and the breadcrumb line under every doc's H1 is no longer seeded — the doctor flags a leftover one instead.
- Install dropped its optional-protocol offer step (it targeted the retired scan routine anyway): a system routine's protocol set is fixed by design, and extras are the operator's own `lazy-routine.offer-protocols` call.
- The catalog paints itself on two channels instead of one. Every document is born carrying the icon its own type declares — a project's own document type declares its `icon` / `color` beside its flags and needs no other edit — while an asset's folder takes its colour from a new `spec_state` key the coordinator writes on the same wake that rewrites the status brief, so the file explorer shows at a glance which assets are drafting, under review, being built, tested, blocked, waiting on the operator, or done. Requests, journals, the decisions registry, and container folders stopped being colourless too, and a declared colour is finally written double-quoted — a bare `#rrggbb` had been parsing as a YAML comment.
- A spec catalog's wiki scope now skips unfinished work by default: install seeds the covering scope with a `spec_stage` allow-list (only `approved` documents — and documents that carry no stage at all — are curated), plans and reports are excluded by name, and the axis pair `product` / `category` lands in the repository-wide vocabulary with one call instead of a per-scope loop. The seed goes through the wiki plugin's new `ensure-scope-config` verb, never touches an operator's own predicate for the same key, and is free to re-run.
- The catalog's container shelves stopped shipping unpainted: every upstream source's repo-level folder-note renders with a default fork icon, the first upstream tick seeds a write-once `upstream/upstream.md` catalog note with a download icon riding the first source note's own commit, the vault-root request inbox carries its `LiInbox` seed, and product registration guarantees a folder icon — declining the wizard's icon question now falls back to `LiPackage` instead of an icon-less note.
- Container colour became a three-tier rule instead of one flat neutral. A product root keeps the neutral `#64748b` so products read apart from the group folders beneath them; an ordinary group folder now carries no colour key at all, since colour is the state axis and a shelf has no state; and the intake shelves — the vault-root request inbox and every upstream note — carry a `#f0abfc` accent chosen to sit outside the state palette, so the places unprocessed material lands are findable at a glance and can never be misread as an asset in some state. A type's declared colour still reaches its asset status notes; it no longer leaks onto the group folder its `default_path` names.
- A markdown attachment's stage became a mirror of its owner's. `lazy-spec.set-stage` now refuses an attachment as a direct target and instead cascades every owner stage change onto the owner's attachments — same `spec_stage`, same `spec/<stage>` tag, same commit — skipping only an attachment sitting in its own review, which the coordinator re-stamps on the wake its finalize raises; the coordinator's reconciliation also stamps a newborn attachment and the doctor flags a broken mirror. The attachment's own review verdict stays in `review_result`, and the spec-catalog wiki preset keeps a rejected attachment out of curation on that key rather than through its stage.
- The catalog gained a system level above assets: the product-root `design.md` / `tech.md` pair — and an optional project-wide pair loose at the content-root, declared by nothing but the files' existence — are typed `system-design` / `system-tech` with review classes of their own, where a system designer writes the design and the architect writes the tech spec. The validator roster was recomposed around one rule: the architect validates everything design-shaped (asset design, system design, and the code plan), the developer validates the test plan, and no class is validated by its own writer. The role vocabulary follows the work: the code implementer is now the developer, the data implementer the data writer.
