# lazycortex-specs — changed since publish

**Status**: changed — version `6.2.0` is ahead of the published `6.1.0`; the pending cycle below ships with the next publish.

## Highlights since 6.1.0

- Asset folder-notes stopped collecting automation noise: the coordinator-watch worker records its wake bookkeeping in a gitignored dispatch-cursor sidecar instead of `# History` lines and unconditional commits, the engine-owned section explainers render as editor-only `<!-- ... -->` comments (legacy italic migrates on the next heal), and the coordination playbook now caps `# Status brief` at a few sentences of product-language state — no document synopses, no wake mechanics.
- BREAKING for the request flow: applying an accepted request now scaffolds only the asset folder and its status folder-note — no documents are seeded and no review opens at apply. Every document (design included) is born from its launch checkbox through the new `seed-doc` primitive: the tick seeds an empty skeleton inheriting the note's request attribution and opens review at the writer round when a source request exists, or waits for the operator's own draft commit when none does. Routing lines lost `docs=` and per-target `:: description` tails (old blocks still apply, the fields are ignored), and an attach lands attribution instead of an attention callout.
- The upstream tick can no longer strand the daemon on a dirty tree when killed under load: a unit note is rendered fully painted (its status icon resolved from the plugin's own registry at render time) and reaches its final path only after the slow repaint subprocess has returned, one syscall before staging — the write-to-commit window a timeout SIGKILL used to land in is gone.
- The coordinator's rule chain gained a group level: a container folder-note between the product root and an asset now carries its own operator-authored `# Coordinator rules` section, so constraints for a whole batch of assets live on the group note instead of being repeated per asset. The chain is read top-down with the layer closest to the asset winning on conflict; group-note templates seed the section, every coordinator job's context now carries the container notes on the asset's path, and `lazy-spec.doctor` warns (with an `--apply` scaffold) on product or container notes still missing it. `# Coordinator commands` stays asset-only.
